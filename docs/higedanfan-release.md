# 115万キロのファンノート

公開先：https://katakatalab.com/higedanfan/

楽曲データとアプリの編集元は [higedanfan](https://github.com/katakata0522/higedanfan)。この版のソースは [fe2de3f](https://github.com/katakata0522/higedanfan/tree/fe2de3f04a7ffa7d17051faf365f906ddfe9bacd)。Node.js 24 で npm ci、npm run lint、npm test、npm run build の順に実行する。

聖地マップは場所とバンドのつながりで絞り込み、複数の分類に属する場所はそれぞれに表示する。広域しか確認できない撮影地は地図の範囲を明示し、訪問案内をしない場所には地図や訪問記録を表示しない。

生成された index.html、`songs/<楽曲ID>/index.html`、assets 内の JS と CSS、third-party-licenses.txt を higedanfan/ に入れる。未使用の旧バンドルを残さない。開発用設定・API キーは含めない。現在の独立ページは全90曲で、それぞれの紹介文に共通テンプレートを適用する。

タブ・ホーム画面のアイコン・共有画像（オリジナルの4ファイル）および Apple Music 公式バッジ SVG（`badges/listen-on-apple-music-ja.svg`）は、編集元の `brand/` にあるファイルを使用する。Publicでは実画像・SVGをGitに含めず、`qa/published-dependencies.json` にサイズ・SHA-256とCI用の代替画像を登録する。本番ではPrivateの `higedanfan/` に置いた実ファイルを `privateOverlay` のSHA-256と照合して配信する。

楽曲ページ90曲は、Apple Music（`https://*.mzstatic.com`）の検証済みジャケット画像と公式バッジを表示し、CSPの `img-src` で同ドメインを許可する。既存の挿絵素材（`song-art/`）は同じ素材経路で保管し、Privateの照合契約を維持する。

マイセトリの追加は、通常の保存を待つ間、同じタブのセッションストレージにも記録する。再読み込み後は既存の保存データと照合し、別タブで削除・初期化された曲を古い操作で戻さない。

テンポは資料によって拍の数え方や数値が異なるため「約」を付ける。資料差が大きく採用を保留した７曲は「調査中」とし、テンポ順と平均から未確定値を除外する。曲別の参考値・別表記と照合状況は、編集元の `docs/bpm-audit-2026-11-08.md` に記録する。

公開ビルドではファンサイトの全HTMLを共通アクセス解析の注入対象から外す。プライバシーポリシーと一致させるため、解析コードが混入した場合はビルドを止める。

トップの入口は projects.json が正本。変更後に node scripts/build-project-cards.cjs で index.html を再生成する。配信時は通常の Private pin 手順に従う。

マイソング診断の結果は、おすすめの曲名と大きなYouTubeプレビューから表示する。回答の変更は末尾の閉じた「条件を変えて探す」にまとめ、再診断とコーナー移動も結果より後に置く。結果表示時は曲名へフォーカスとスクロールを合わせる。

診断の設問切り替えは180ms、結果の表示は220msの控えめな動きを付ける。合計演奏時間は値が変わったときだけ240ms強調する。静止時の配置・色・文字サイズと試聴枠を維持し、動きを減らす設定では演出を止める。

マイセトリはM01・EN1表記を保ち、曲名と曲順を入力欄より先に見せる。曲名はスマホでも18pxで表示し、上下矢印は曲の枠の外側の細い欄へ分ける。曲ごとの「操作」ボタンは置かず、追加・タイトル変更・アンコール・先頭移動・削除は共通編集欄へまとめる。コピーは一覧直後、保存案内と詳細な集計は一覧より後から開ける。音域一覧は横スクロールと見出しの昇降順ソートに対応し、音の高さで比較する。アルバム・年代・曲調・声の範囲は閉じた条件欄へまとめ、キーワード検索は曲名・読み・タイアップを先に置く。英字タイトルは原題、日本語タイトルはローマ字や英語由来の綴りを補助検索語に使い、全90曲の3表記検索を検査する。

コンテンツ移動はサイト名とハンバーガーメニューに統一し、独立した全90曲のページにも公開コンテンツを並べる。曲ページから戻ると検索条件・表示件数・表の並び順を復元する。旧HTMLを開いたままの利用者が遅延読み込みする可能性がある直前のハッシュ付きアセットは、互換用として保持する。

セトリの追加方法は曲名検索とアルバム選択を切り替える。追加・編集欄にはBPMを表示せず、曲順の分析はグラフを先に、平均テンポや計算の説明は閉じた「数値と見方」にまとめる。

聖地マップは抽象図柄と重複する導入を省き、場所カードは場所名から表示する。MVなどの関係が確認された曲と、作成者が散策用に選んだ曲を区別し、後者はカード下部に置く。分類・地図・訪問記録・重要な注意書きは保持する。

歴代ツアーは検索と一覧を先に表示し、照合方法の説明と保存・引き継ぎは一覧より後から開ける。クイズは「Official髭男dism検定」とし、1回10問・全60問の構成で、並べ替え専用コースは設けない。

参考記事・インタビューは、曲解説と検定で参照した138のURLを132件の資料にまとめ、記事名・媒体・掲載元URLと確認できる日付を表示する。問題・正解・難易度は資料一覧に置かない。公開日不明は明記し、更新日・放送日・発行日・資料発売日を区別する。記事名・曲名・媒体・日付の検索、媒体選択、日付の昇降順と24件ずつの追加表示に対応する。分割ページと移転前URLの対応を保ち、開けない資料は別に表示する。検定の回答・保存形式は保持する。

トップ画面には初回訪問時のみの「ヒゲくるん」オープニング（メニューから再再生可）と、手書き見出しフォント（`Kaisei Decol`）を使った付箋ノート・4人メンバー紹介を配置する。編集者プロフィール（`#editor`）を新設し、複数のマイセトリ保存とPNG画像カード書き出しに対応した。JSON形式のバックアップ・復元UIはプライバシーポリシー（`#privacy`）とフッター導線へ集約し、全コーナー見出しとカード説明は体験価値先行の表記へ統一した。
