# KatakataLab 収録13ツール 辛口・多角的レビュー総まとめ

- **対象範囲**: `katakatalab-web` 内に元ソースがあり、そのまま改修・リファクタリング可能な主要13ツール
- **検証方法**:
  - ヘッドレス Chromium 実機レンダリング検証（PC `1440×900` / スマホ `390×844`）
  - DOM計測（横はみ出し、ファーストビュー到達位置、タップ領域サイズ、コンソールエラー／失敗リクエスト）
  - ソースコード精査（HTML / CSS / JS構造、外部CDN依存、テーマ保存キー、アクセシビリティ、保守性）
- **評価観点**: ①使い勝手・直感性 ②PC/スマホ表示品質 ③デザイン統一感・ダークモード ④コード品質・保守性・オフライン耐性 ⑤遊び心・独自性・ワクワク感

## 0. 全体総評（辛口スコアカード）

KatakataLab の13ツールは「ブラウザ完結・個人情報を外へ送らない・実用目線」という思想が一貫しており、**機能の作り込み（特に同人計算機・スクショ端カット・Gravity TODO・強調線）はかなり高水準**です。

## 1. 全13ツール横断で見えた「7つの構造的な弱点」

個別のバグ以前に、サイト全体で共通して足を引っ張っている設計負債が7つあります。

1. **ダークモードと保存キーの深刻な分裂**
   - トップページは `localStorage.theme`（`body.dark-mode`）を使う一方、各ツールは `doujin_dark_theme`、`password-gen-theme`、`fontlab-dark-mode`、`prefers-color-scheme` のみ、切替ボタンなし、完全ライト固定（`screenshot-crop`）、完全ダーク固定（`qrcode`、`emphasis-lines`）とバラバラ。トップでダークモードにしても、ツールを開いた瞬間に白画面で目を焼かれます。
2. **ヘッダー／パンくず（`tool-chrome.css`）の不統一と二重ヘッダー**
   - `doujin-calc`、`screenshot-crop`、`gravity-todo` は `tool-chrome.css` 未導入。逆に `font-lab` と `emphasis-lines` は独自ヘッダーの上に `tool-chrome` を載せてしまい**二重ヘッダー**になっています（特に `emphasis-lines` は暗色スタジオ画面の上に真っ白な帯が乗り違和感大）。
3. **外部CDN依存と「ブラウザ完結・PWA」の矛盾**
   - `doujin-calc` は `sw.js` でPWA化しているのに本番で `https://cdn.tailwindcss.com`（Tailwind Play CDN）を読み込んでおり、コンソールに公式警告が出るうえオフラインで崩れます。
   - `text-diff` は `cdnjs.cloudflare.com` の `jsdiff` に全面依存しており、CDN障害・オフライン環境で機能停止します。
   - `emphasis-lines` は未同梱バイナリフォント（Phosphor `.woff2`）に依存しており、フォント読込前は全アイコンが豆腐化します。
4. **「防御的な注意書き・言い訳」がファーストビューを圧迫**
   - `password-generator`、`ogp-simulator`、`aspect-ratio-calc`、`px-rem-converter`、`gravity-todo`、`qrcode` で「〜は検査しません」「〜の保証ではありません」「〜は含みません」といった防御的テキストが操作欄より上に陣取っています。誠実さは美点ですが、**ツールを開いた瞬間のワクワク感と即応性を著しく削いでいます**。注意書きは折りたたみ（`<details>`）や結果下部に逃がすべきです。
5. **ブラウザ標準 `alert()` / `confirm()` / `prompt()` の残存（6ツール計16箇所）**
   - `password-generator`、`discount-calc`、`screenshot-crop`、`ogp-simulator`、`seireki`、`gravity-todo` に残存。iFrameやモダンブラウザで体験がチープになり、操作を強制ブロックします。共通のトースト＋軽量確認モーダルに統一すべきです。
6. **インライン `style=` の肥大化と命名の揺れ**
   - `password-generator`（53箇所）、`px-rem-converter`（50箇所）、`font-lab`（40箇所）、`qrcode`（21箇所）などHTML内のインラインスタイルが多く保守性が低い。また、トップページのカード名（例：「縦横比を計算する」「安全なパスワードを作る」）とツール内のH1（例：「アスペクト比計算」「パスワード一括生成くん」「Text Diff Tool」）が一致しない箇所が目立ちます。
7. **「お試しサンプル（1クリック体験）」と遊び心の不足**
   - 実用ツールは「空の入力欄」から始まるものが多く（`qrcode`、`text-diff`、`ogp-simulator`、`screenshot-crop`、`seireki`）、開いた瞬間に「おっ、便利そう！」と感じる前に手が止まります。初期サンプル表示や1クリック試用ボタンを入れるだけで第一印象が劇的に変わります。

### ① 同人の価格と釣銭（`doujin-calc/`）

- **構成**: HTML 950行 / JS 1,979行（7分割＋SW） / CSS 211行 / 計509KB
- **特徴**: PWA・オフラインSWあり / 独自ダークモードあり / `tool-chrome.css` 未導入 / 英語なし

#### 強み
- **圧倒的な現場解像度**。見本誌・スケブ分の除外、お釣り快適度（★評価）、当日レジカウンター（キーボード `[1]〜[4]` 対応）、消化率スライダー、メロン／BOOTH手残り比較、持ち物チェック、お品書き・アンソロ精算書コピーまで「同人作家が本当に欲しい全部」が詰まっています。
- スマホ下部の固定4タブナビ（部数・原価／価格比較／マルチレジ／釣銭準備）も導線として優秀。

#### 辛口指摘（UI・UX・PC/スマホ）
- **PC版で「締切プラン」ラベルが `締切プラ / ン` と1文字折り返し**になっている（1440px幅でも発生）。
- **スマホ版ページ総高が約5,981px**と極めて長い。全機能を1ページ縦積みにしているため、当日現場で「マルチレジだけ開きたい」時に誤スクロールしやすい。タブ切替（ビュー分離）またはセクション折りたたみがあると現場耐性が跳ね上がります。
- **レジカウンターの固定価格制限が惜しい**: 「セット1,500円・既刊500円・グッズ800円は固定です」と明記されているが、現場で一番変えたいのは既刊とグッズの値段。編集できないと実用性が半減します。
- タイトルの `Pro` バッジは無料／有料の区分がないため、やや誇張（AI生成ツールっぽさ）に見えます。
- ページ下部の「おすすめサークル備品セレクション（PR）」がAmazon検索URLへのリンクになっており、せっかくの高品質ツールの最後が少しアフィリエイト記事っぽく見えます。

#### 辛口指摘（コード・技術）
- **致命的**: 本番HTMLで **`https://cdn.tailwindcss.com`（Tailwind Play CDN）** を読み込んでおり、コンソールに公式の警告が出ます。さらに `sw.js` を備えているのに外部CDN依存のため、**コミケ会場の電波死滅環境（まさに一番使いたい場面！）でオフライン起動するとCSSが全崩壊**します。`emphasis-lines` のようにビルド済み `tailwind.built.css` を同梱すべきです。
- テーマ保存キーが独自の `doujin_dark_theme` でサイト共通 `theme` と連動しない。

#### 進化アイデア（遊び心・差別化）
- **「当日レジ専用・誤タップ防止フルスクリーンモード」**（デカいボタン＋効果音＋売上目標プログレスバー＋黒字達成ファンファーレ演出）。
- 既刊・グッズ・セットの単価と商品名を自由に編集＆複数スペース分プリセット保存。

#### 優先改修
- **P0**: `cdn.tailwindcss.com` 撤去→静的ビルドCSS化（真のオフライン対応）／PC `締切プラン` 折り返し修正
- **P1**: レジ商品の単価カスタム編集対応／`theme` キー統一
- **P2**: 当日レジ専用モード＆黒字達成のささやかな祝福演出

### ② QRコードを作る（`qrcode/`）

- **構成**: HTML 805行 / JS 3,789行 / CSS 1,758行 / 計845KB（最大規模）
- **特徴**: `tool-chrome.css` 導入 / 英語あり / SWあり / manifestなし / ダーク画面固定

#### 強み
- 外部CDNに頼らず完全ローカルでQR生成でき、Wi-Fi・連絡先・メールなどの用途別入力＆ガイド群まで整っている。プライバシー面の説得力が高い。

#### 辛口指摘（UI・UX・PC/スマホ）
- **スマホのファーストビュー圧迫が深刻**: 390px幅で開くと、上から「パンくず」「タイトル・説明」「横いっぱいの `日本語 | English`」「横いっぱいの `⚙ 詳細設定`」「横いっぱいの `🔒 Client-Side Only`」が縦に並び、**画面の上半分（約430px）を占有**。入力欄に辿り着くまでが遠すぎます。
- **`🔒 Client-Side Only` のアフォーダンス誤認**: ボタンと全く同じ横幅・角丸・枠線デザインのため「押せるボタン」に見えますが、ただの静的ラベルです。
- **初期プレビューが空の白枠**: 「テキストを入力すると即座に表示されます」という絵文字プレースホルダのまま。最初からサンプルURL（例：`https://katakatalab.com`）のQRを出しておけば、色変更やサイズ変更を即座に体感できます。
- **Pro機能のSVG/PDF仕様が弱い**: UI自体に「どちらもPNG画像を内包し、拡大しても細部は増えません」と書かれています。正直なのは誠実ですが、ベクターSVG出力はQRコードのモジュール配列から `<rect>` で数行書けるため、本物のベクターSVGにすれば品質も説得力も一気に上がります。
- **ライトモード非対応**（テーマ切替ボタンが見当たらない）。また、スマホ下部の固定バー（用途／設定／保存）が入力欄下端と視覚的に干渉しやすい。

#### 辛口指摘（コード・技術）
- `script.js` ＋補助JSで計3,789行、CSS 1,758行、HTML内インライン `style=` が21箇所、さらに `playwright.config.js` が本番ツールディレクトリ直下に混在。責務整理の余地が大きい。
- `sw.js` はあるのに `manifest.json` がない（PWAとして中途半端）。

#### 進化アイデア（遊び心・差別化）
- **本物のベクターSVG生成**＋「スマホカメラで本当に読めるか？」の**コントラスト自動判定バッジ**（薄い色を選んだときに「読み取りにくい配色です」と警告）。
- 名刺・店頭POP・Wi-Fi案内カードをその場でA4/L判印刷レイアウトできる「Wi-Fi案内ポスター即席生成」。

#### 優先改修
- **P0**: スマホ上部のボタン3段積みを1行コンパクト化＋`Client-Side Only` を非ボタン表現に変更
- **P1**: 初回サンプルQR即時描画＋本物のベクターSVG生成へ刷新
- **P2**: ライト／ダーク両対応、Wi-Fi案内カード印刷テンプレート

### ③ 安全なパスワードを作る（`password-generator/`）

- **構成**: HTML 486行 / JS 1,869行（`pwd-logic.js`, `vault.js`, `script.js`） / CSS 1,340行 / 計149KB
- **特徴**: `tool-chrome.css` 導入 / CSPあり（全13ツール唯一！） / PWA（SW＋manifest） / ダーク切替あり

#### 強み
- **全13ツール中で唯一しっかり `Content-Security-Policy` を設定**しており、セキュリティツールとしての姿勢が立派。
- 「生成」と「診断」の2モード、文字種ごとの色分け表示（大文字・小文字・数字・記号）、Wi-FiやPINプリセットなど実用性が高い。

#### 辛口指摘（UI・UX・PC/スマホ）
- **スマホのファーストビュー完全崩壊**: 390px幅で開くと、上から「パンくず」「2行に割れたタイトル `パスワード一括生成 / くん`」「説明文」「**スマホでは押せない `Ctrl+G / ⌘+G` のPCキーボード案内**」「システム監視っぽい緑の `● オンライン` バッジ」「ガイド案内3行」「モード切替」が**約650px**も続き、肝心の**生成されたパスワードが1件も画面内に見えません**（入力欄開始位置 `y = 1,095px`）。
- **タイトル折り返し**: モバイルで `くん` だけが2行目に孤立。しかもトップページ名「安全なパスワードを作る」とH1「パスワード一括生成くん」でトーンと名称が大きく乖離しています。
- **`● オンライン` ステータスバッジ**: ユーザーにとって不要なシステム状態表示（UIノイズ）。オフラインになった時だけ小さく「オフライン動作中」と出せば十分です。
- **生成結果がスマホで設定パネルの下に追いやられている**: パスワード生成ツールを開いた人は「まず1クリックで即コピー」したいのに、スマホでは設定欄を全部スクロールしないと結果が出ません。スマホでは「結果（上）→設定（下）」の順が鉄則です。

#### 辛口指摘（コード・技術）
- **HTML内インライン `style=` が53箇所**（全ツール中最多）。スタイル管理がCSSとHTMLに散乱しています。
- `vault.js` が存在する一方、画面上では「作成専用ツールです」と案内しており、未使用または非表示機能のコードが残っているか要整理。
- 共有コピー失敗時に `prompt()` を使用。また `localStorage` に `theme` と `password-gen-theme` の2キーが混在。
- モバイルでタップ領域32px未満の小さい要素が15箇所検出。

#### 進化アイデア（遊び心・差別化）
- **「覚えられる日本語／英語パスフレーズ生成（Diceware風）」**（例：`neko-ramen-sora-42`）を追加すると一気に差別化できます。
- 強度バーに「総当たり解読の目安時間（例：スパコンでも約300年）」を視覚的に表示すると、学ぶ楽しさと納得感が出ます。

#### 優先改修
- **P0**: スマホでは「生成結果→設定」の順に配置換え＋前置き・PCショートカット案内（スマホ非表示）・`● オンライン` 撤去
- **P1**: インライン `style=` 53箇所をCSSへ整理、`prompt()` をコピーUIへ置換、タップ領域拡大
- **P2**: パスフレーズ生成モード＋解読時間ビジュアル演出

### ④ Webフォントを比較する（`font-lab/`）

- **構成**: HTML 674行 / JS 504行 / CSS 1,120行 / 計118KB
- **特徴**: `tool-chrome.css` 導入 / 英語あり / ダーク切替あり / SW・manifestなし

#### 強み
- テキストを直接書き換えながら日本語Webフォント＋サイズ・太さ・行間・字間を触ってそのままCSSコピーできる着眼点は素晴らしい。「フォント見本市」「技術コラム」まで備え、読み物としての熱量も高い。

#### 辛口指摘（UI・UX・PC/スマホ）
- **【致命的バグ】PC初回表示でメインプレビュー欄が真っ白な空箱に見える**: `1440×900` で開くと、左側のプレビュー枠（`.preview-container-wrapper`）は右側の長い設定パネルに合わせて縦に引き伸ばされ、さらに `display: flex; align-items: center;` が掛かっているため、**肝心のサンプル文章が縦中央（画面下端より外）に押し下げられ、ファーストビューには「適用完了！」バッジが浮いた真っ白な空き箱しか見えません**。初見ユーザーは「壊れている」と誤認して即離脱します。

### ⑪ 縦横比を計算する（`aspect-ratio-calc/`）

- **トップページとの名称不一致**: トップカードは「縦横比を計算する」、ツール内は「アスペクト比計算」。
- **ネガティブ始まりのリード文**: 「画像ファイルの読み込みや切り抜きはしません。ピクセル計算と枠プレビューの道具です。」→ 「しないこと」より「できること」を先に伝えるべきです。

### ⑫ px / rem 変換（`px-rem-converter/`）

- **構成**: HTML 334行 / JS 510行 / CSS 780行 / 計73KB
- **特徴**: `tool-chrome.css` 導入 / 英語あり / OS連動ダークモードのみ（切替ボタンなし） / 外部CDNゼロ

#### 強み
- 外部CDNゼロ・73KB。`16px` / `10px` の基準サイズ切替、編集可能なライブプレビュー（宮沢賢治テキストの味わい）、早見表がまとまっており、Web制作者が欲しいツボを押さえています。

#### 辛口指摘（UI・UX・PC/スマホ）
- **PC版だけ長い技術注記がコンバーターより上にある**: スマホ版では「基準サイズ→PX/REM入力→青い注記ボックス」の順で使いやすいのに、PC版では「ヘッダー→**4行の長い青い技術解説ボックス（`font-size: 62.5%` の解説など）**→PX/REM入力」になっており、一番大事な入力欄が下に押されています。PCも入力欄を最優先で上にすべきです。
- **1クリックコピーが主変換枠にない**: 変換した `1.5rem` をそのままCSSに貼りたいのに、入力欄の横にコピーボタンがなく手動選択が必要。
- **ダークモード切替ボタンがない**。またH1が英語 `PX / REM Converter` で日本語UIとややズレています。

#### 辛口指摘（コード・技術）
- **HTML内インライン `style=` が50箇所**（`password-generator` に次ぐワースト2位）。早見表や説明ブロックのスタイルをCSSクラスへ整理すべきです。
- `innerHTML` ゼロ、`alert` ゼロで安全性は高い。

#### 進化アイデア（遊び心・差別化）
- **「レスポンシブ `clamp()` 自動計算タブ」**（最小画面幅375pxで14px、最大1440pxで20px → `font-size: clamp(0.875rem, ..., 1.25rem);` を一発生成＆ブラウザ幅スライダーで拡大縮小プレビュー）。これが付くだけで並のpx/remツールから頭ひとつ抜けます。
- **Tailwind CSSクラス対応表示**（例：`16px = 1rem = text-base / p-4`）。

#### 優先改修
- **P0**: PC版の青い技術注記ボックスを入力欄の下へ移動（モバイル順と統一）＋結果の1クリックコピー追加
- **P1**: インライン `style=` 50箇所のCSS化＋ダークモード切替ボタン追加
- **P2**: `clamp()` フルードタイポグラフィ計算＋Tailwindクラス換算表示

### ⑬ Gravity TODO（`lab-tools/gravity-todo/`）

- **構成**: HTML 239行 / JS 2,703行（15クラス分割＋Matter.js） / CSS 1,001行 / 計221KB
- **特徴**: `tool-chrome.css` 未導入 / 時間帯自動テーマ（`TimeTheme.js`） / PWA（SW＋manifest） / BGM・SE・ジャイロ対応
