# PikaLab 3D列車の島 — v0.5 マップ拡張・線路干渉防止・描画最適化

淡い黄緑の草地・クリーム色の崖・青緑の海に浮かぶ、**立体メッシュで作った鉄道模型**を操作する学習ゲームです。もとの低ポリゴン浮島の参考画像の世界観を目標としていますが、精密な同一シーンの再現ではありません。

## 操作

1. **「はやさを変える ↓」**で操作台へ。A（赤）・B（青）の列車の速さを12〜48 km/hから決める。
2. **「列車を走らせる」**で3D島へ戻り、2台の走行を観察する。
3. 到着すると島の上に結果が出る。**「グラフを見てみる ↓」**から走行距離の線を確かめる。失敗した場合は速さの調整方法を読む。
4. **「もどす」**で設定を変えて再挑戦。待てない場合は走行中の **「結果へ進む」** を使える。

3D模型：ドラッグで視点回転、**Shift＋ドラッグで島を平行移動**、**スマホでは2本指ドラッグで島を移動**、右下の ± で拡大・縮小、⟲で初期視点へ。マウスホイールは通常のページスクロール、Ctrl/Cmd+ホイールで3Dを拡大・縮小できます。スマホは縦スワイプでページをスクロールできます。キーボードでも3D模型にフォーカス後、**矢印キーで視点回転、+/-で倍率調整、Rで視点リセット**ができます。

動きを減らす設定では走行を短縮し、結果をすぐ表示します。静的HTML単体・完全オフラインでゲーム自体を実行できます（PikaLabトップへの明示的なリンクをクリックした場合は別）。

## 実装の要点

- `world3d.js`：3D多角形メッシュ・15の段状の島・層状の崖・波打ち際・木・花・石・小屋・駅・風車・橋・線路・列車・3Dカメラ。
- `game.js`：**両路線を1200mと仮定した**到着時刻計算、列車A/Bの進行、走行記録のグラフ描画、結果とヒント。モデル式は `距離[m] = 時速[km/h] × 1000/60 × 経過時間[分]`（1200mで停止）。
- **客車ごとに線路曲線の異なる地点と接線から座標を計算**。列車を単に直線移動させず、曲線に合わせて位置・方向を変えます。
- **15島（旧9島）までマップを拡張**。西側・東側・奥・手前に6島を追加し、A路線9.43→14.74単位、B路線19.14→26.96単位に延長。模型上の形状・距離の変更のみで、学習上はどちらの駅まで1,200mのまま。
- **線路安全帯**：風車・家8件について、線路の曲線上での最近接距離と建物・風車羽根の占有幅から安全位置を探索。候補位置が不適切なら安全な場所へ移し、適切な位置がない場合はモデル構築を失敗させる。木も線路と建物の双方から離して配置。
- 線路近くの木を減らし、駅や列車を隠しにくくする。水際の薄い3Dフォーム、淡い草地、立体の車輪などを追加。
- ブラウザが利用できればWebGLで3D三角形を描画。**静的な島の頂点はGPUへ1度だけ送信し、カメラ回転はシェーダーのパラメータで処理**。禁止環境では同じ**3D幾何をCanvas2Dへ投影**して描画し、静的な島の投影座標はカメラ移動時だけ再計算。静的/動的な面の深度ソートは2つのリストの線形マージに変更し、画面外の面は描画から除外。待機時の余計なタイマー/RAFを削減し、走行時の描画も上限を設定。SVGグラフは約100ms間隔で動く線だけ更新。
- 広告・アフィリエイト・第三者解析・外部ランタイムCDNを含めません。学習済み情報やユーザー名は保存しません。`noindex,nofollow` のままです。

**注意**：島の線路は2本とも見た目の長さや高さが異なります。1,200mという距離は教材用の仮定であり、島の3Dスケールは現実の距離比には対応しません。速さと到着時刻の算数的な関係を学ぶモデルです。

## 品質確認

```sh
node --check world3d.js
node --check game.js
node --test tests/*.test.cjs
python tests/quality-v05.py
python tests/quality-v04.py
python tests/standalone-check.py
python tests/ux-regression.py
```

- Node計算・3D曲線・カメラの自動テスト：**21件合格**。
- ローカルChromiumにて320/390/768/1280pxの描画（v0.5：15島、建物8件、2本指移動を含む）、回転、走行、停止、成功・失敗・再挑戦、グラフ、ページ遷移を確認。横はみ出しとJS例外は検出されていません。
- スマホで縦スクロールが可能な `touch-action: pan-y`、3Dキーボード移動、初期倍率リセット、グラフの答え先出し防止、`prefers-reduced-motion` を検証。
- この検証環境はローカルHTTPとWebGLが制限されます。そのため Chromium の `about:blank` へ**同一のHTML/CSS/JSを注入して**テストしました。ソフトウェア3Dフォールバック経路は検証済みですが、**GPU WebGLの実機描画・長時間モバイル負荷・iOS Safari・実際の子どもによる操作検証は未完了**です。WebGL経路はAPIモックによる単体テストでのみ確認しています。

- 学習上の大きな修正として、**グラフの横軸を0〜6分で固定**しました。速さごとの線の傾きを同じ縮尺で比較でき、結果が出た後には簡潔な理解のヒントを表示します。
- 造形は島の草と崖の色、駅の瓦屋根/ホーム、橋の床板と支柱、小屋の玄関、水面の反射を実3D形状で補強しました。

## ファイル

- `index.html`, `style.css`, `world3d.js`, `game.js`: アプリ実行に必要。
- `tests/core.test.cjs`: 数学・モデル検証。
- `tests/webgl-pipeline.test.cjs`: WebGLの静的/動的VBO分離をAPIモックで検証（実GPU試験ではありません）。
- `tests/quality-v05.py`: 線路衝突を避けた15島、2本指カメラ移動、走行・停止・正誤・レスポンシブを検証。
- `tests/quality-v04.py`: 全画面幅と再生・一時停止・グラフ・カメラ・スクロール・描画キャッシュ検証。
- `tests/standalone-check.py`: 4画面幅で3D操作と正誤を確認。
- `tests/ux-regression.py`: 子どもの操作動線・キーボード・減速設定・グラフのテスト。
- `tests/browser-check.py`: 開発用の初期ブラウザ操作テスト。
- `docs/QUALITY_NOTES.md`: UX品質と追加課題。
