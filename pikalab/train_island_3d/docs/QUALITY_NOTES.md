# 3D列車の島 v0.6 — 広い本島と高い離島（2026-10-16）

## 設計変更の理由

前版は15島に分かれていて、線路が限られた島々の狭い範囲に集中していました。ユーザーから「地図全体を使い、平地を増やし、標高のある場所は離島にしてもいい」という指摘を受けたため、島の数を増やす方針から撤退しました。

## 実装

- 1つの広い本島を不規則な18頂点の海岸線から生成。線路を完全に平地内に通し、中央駅を中心とした地域へ住宅5軒・農地・森を分散。
- 標高2.7〜3.5の7つの離島を周囲へ配置。風車は本島のレールから離れた別島に移動し、装飾を保ったまま貫通リスクを排除。
- A線 36.69、B線35.07の3D弧長（いずれも旧版より長い）。中央駅側の最終座標は据え置く。
- 線路が地面のポリゴン裏へ隠れる不具合を修正。大きすぎる地表ポリゴンを約1.28単位の格子で分割し、本島境界でクリップする。
- ランドマークの安全配置は従来の楕円だけの近似でなく、本島の不規則な**本当の外周**と距離計算に対応。
- 木は列車・建物との安全帯を確保しながら新しい平地へ分散。模型全体の静的頂点キャッシュは維持。
- 広い地形を走る様子が見やすいよう、ゲームの仮想時間の進行を少し遅くした。

## 実施確認

- Node 25件成功。全ルートが平地内・一定高さ・地図の東西南北を使用し、建物が崖から浮かないことを確認。
- Chromium 320/390/768/1280で、本島の描画・回転・2指移動・走行・結果とグラフの基本動作、横はみ出しなし。
- 実GPU WebGLと実機・負荷・支援技術は未確認。従来の完全品質保証とは見なさない。

# 3D列車の島 v0.5：線路貫通の修正とマップ拡張（2026-10-16）

## ユーザーからの不具合報告

風車・家が線路の上にあり、走る列車が建物を貫通する。建物自体のデザインは残し、線路の外側に移動してほしい。またマップを広くして遊べる範囲を増やしてほしい。

## 原因と対処

- v0.4では風車中心がB路線から約0.53模型単位、海辺の家が約0.05単位の位置に固定されていた。
- 建物の座標を `LANDMARK_SPECS` に統一し、`layoutLandmarks()` が3D鉄道の曲線から最短の**水平距離（XZ）**を求める。建物の幅・風車羽根の回転半径に**1.15単位の線路側余裕**を加え、安全な島の上にのみ配置する。安全な位置がない場合はエラーにして、問題を放置しない。
- 風車の羽根の回転座標は、別の固定値ではなく、配置済み風車座標から毎フレーム生成する。これにより本体だけ移動し羽根が旧座標に残る回帰を防ぐ。
- 木も同じ線路判定と建物の占有範囲を使い、自動的に干渉を避ける。
- 建物・風車が島の草地の外側にはみ出さないよう、島の幅と建物の半径を用いて配置制限。

## マップの変更

| 要素 | v0.4 | v0.5 |
|---|---:|---:|
| 浮島 | 9 | 15 |
| A線模型の弧長 | 9.43 | 14.74 |
| B線模型の弧長 | 19.14 | 26.96 |
| 見た目の地形/軌道 | 水上の9島 | 左右・奥・手前の合計15島、両路線を延長 |
| 建物衝突チェック | 一部の木のみ | 風車・家8件と木々を自動検証 |

- 学習の距離は両方1200mとする**教育上の仮定**で、模型の長さが同じではないことは維持する。列車の速度表示・到着時刻・0〜6分固定グラフは変更しない。
- カメラの画角を新しいマップへ合わせ、**Shift＋ドラッグ／Shift＋矢印キー／スマホの2本指ドラッグ**で水上の島を平行移動して探索できるようにした。通常のドラッグ回転、スマホの1本指縦スクロール、拡大・縮小ボタン、リセットを維持する。
- WebGLパイプラインはカメラの注視点を `uTarget` uniform として渡す方式へ更新。ソフトウェア版の静的シーンキャッシュキーにも注視点を含める。
- ソフトウェア3Dレンダラは、静的面を画角変更時にだけ投影/ソートし、毎フレーム変化する面だけをソートして**線形マージ**。画面外ポリゴンの描画を省く。

## 自動検証

- Node単体テスト **21件合格**：数学、曲線、レール、カメラ、WebGL固定VBO、**全8建物の線路との距離＋島の上の支持、木々の安全配置、拡張した2本の線路**など。
- Chromiumソフトウェアレンダラ、**320/390/768/1280px**で15島の表示、ブラウザ例外なし、横はみ出しなし、Shiftパンと2本指パン、出発、停止、再開、成功/失敗、再挑戦を確認。
- HTML/CSS/JSを1つに束ねたオフライン版を再度操作確認する。

## 未完了の項目

実GPUでのWebGL描画、実機GPU負荷/長時間テスト、iOS/Android実機、児童と保護者の操作テスト、スクリーンリーダー、PikaLab全体のCI/Private配信は未完了。旧版からのHTML/JSとは異なるため、本PRをDraftに保つ。

# 3D列車の島 v0.4 品質改善・検証ノート（2026-10-16）

## 取り組んだこと

1. **GPU効率**：島7,000面以上の静的モデルを毎フレームCPU投影しGPUに転送する方式から、**静的頂点の固定VBO＋カメラ行列に相当するuniform＋動的列車用VBO**へ分離。WebGL APIモックでは静的アップロード1回、島/列車の別描画を確認。実GPU描画は未確認。
2. **Canvas2D効率**：モデルの投影をカメラ/ウィンドウサイズが変わったときだけ再作成。列車が動いても約7,600面を毎回再投影しない。カメラ/ウィンドウ変更でキャッシュを破棄。
3. **描画負荷**：静止時は約440ms間隔、動作中もソフトウェア約48ms・WebGL約28msの上限に調整。ゲーム時刻のループは走行中だけ有効とし、停止/中断/終了でキャンセル。
4. **固定縮尺のグラフ**：従来の速度依存した横軸を、0～6分固定に修正。同じ時刻で2列車の位置を比較できる。グリッドは再生成せず動的な線・点のみ更新。結果後に1つだけ学習のポイントを表示。
5. **画面**：島の地形の色を柔らかくし、駅の屋根・ホーム・家の細部・橋脚・橋の床を立体ポリゴンで追加。PCではコンソールとカメラボタンが重ならないよう配置修正。グラフをスマホでも見やすい幅・文字サイズへ。
6. **操作**：マウスホイールで3Dにズームしてしまいページがスクロールできない問題を解消。Ctrl/Cmd+ホイール、画面の±ボタン、キーボードにも対応。拡大文字2倍でも横はみ出しを確認。
7. **安全/故障時**：JavaScript無効時の説明追加。広告・外部トラッキング・外部CDNは不使用。

## 検証結果

- `node --test tests/*.test.cjs`: **17/17成功**（単位換算・時間・3D線路・メッシュ・カメラリセット・WebGLの固定VBO利用など）
- `python tests/quality-v04.py`: Chromium 320/390/768/1280px、正解/誤答→再挑戦、回転、キーボード、ホイールスクロール、停車時の無駄なRAF、グラフの固定スケール、静的投影キャッシュ、アクセシビリティ設定確認。
- `python tests/ux-regression.py`: 同じ画面サイズ、減速アニメーション、画面移動と結果ヒント。
- `python tests/browser-check.py`: PC/スマホの実描画キャプチャ、JS例外・横スクロールの検出なし。
- ソースのHTTP/fileナビゲーションが管理ポリシーで制限されるため、ブラウザE2EはソースHTML/CSS/JSの文字列を同一文書に注入して実行。**実際のWebGL GPUドライバ試験には該当しません。**

## 残る課題

- **最優先：WebGL GPU実機検証**。開発環境はWebGLをポリシーで無効化しており、今回の描画確認はソフトウェアフォールバックです。Android・iOS・デスクトップGPUで色・面の重なり・フレームレート・描画温度・メモリを評価。
- 参考の画像ほど高精細ではない。特に曲線レールの滑らかさ、橋と段差の接合、トンネル形状、駅の看板・建物の造形を長期改善。
- 実際の子ども/保護者の操作検証とスクリーンリーダーでの理解、キーボードのみでの同じ達成感を追加監修。
- Public CIのフルビルド、PWA、サイト横断広告/解析遮断検証、実サイト遷移テスト。**Draft PRのまま、本番は未公開。**
