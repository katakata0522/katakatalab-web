# PikaLab「動きとグラフの司令室」実装仕様書 v0.1

作成：2026-10-16／実装状態：操作可能な最小縦切り（vertical slice）3ミッション、公開前レビュー版

## 1. 達成目標と非目標

- 主目標：**列車の動きと位置—時間グラフの交点が同じ出来事を示す**ことを、計算式を覚える前に体験して理解できるようにする。
- 体験：「目標を知る → 速さ・出発時刻を1つ変える → 列車を走らせる → グラフで確かめる → 誤差の理由から再試行する」。
- 終了時の学習：グラフの横軸＝経過時間、縦軸＝西の駅からの位置、線の傾きが速度に対応、線の交点が同じ時刻・同じ位置を示す、と自分で説明できる。
- 非目標：一般の3D地形編集、自由カメラ、リアルな鉄道運行シミュレーター、駅と時間を同時に変える複雑な編集、計測追跡、学習成果を裏付けなしに宣伝すること。

## 2. 既存PikaLabとの位置づけ

- PikaLabの親しみやすいクリーム色・丸み・実験室の空気感を共有しつつ、作品固有の主役を**机の上の小さな鉄道模型**にする。
- インタラクティブなSVGと静的CSSを使用する。WebGL/Three.jsは使わず、拡大してもシャープな表現・軽い描画負荷を優先。
- 既存のFraction Lab、Science Maker、ホームのカタログ、共通プロフィールやデプロイ経路を変更しない。実装ファイルは `pikalab/train_graph_lab/` に独立配置。
- 初期版は `noindex` とし、第三者計測・広告・アフィリエイト・外部CDNなし。既存の本番公開はこの段階では行わない。

## 3. 画面と情報の優先順位

1. 上：戻るリンク／タイトル／進捗（余計な英語の飾りラベルなし）
2. 主役：大きなミニチュア鉄道（2車両、中央駅、線路、距離目盛り）
3. 問い：いま目指す出会い地点を1文で示す（余計な説明・勲章を入れない）
4. 操作：変更可能な条件**1つ**、開始・一時停止・やり直し
5. 根拠：グラフ「時間（分）」と「西の駅からの位置（m）」、交点を表示。図と同じ値を使う。
6. 結果：成功か不成功か＋次に直せる具体的な1行、成功なら数学的な意味を短く表示

PCは模型を横幅いっぱいに配置し、その下の操作・グラフを2カラム。スマホは模型→操作→グラフの縦並び。320px・390px・768px・1280pxで横スクロール禁止。数値は図と別にテキストで常時表示。

## 4. ミッションデータ（単位と期待値）

共通：線路長 `L = 1200m`、西駅は `x=0`、中央駅は `x=600`、東駅は `x=1200`、両車両は反対方向へ直進。Aの位置は西駅からの距離、Bは東駅から西へ向かうので位置は `1200 − 走行距離`。速度はkm/h、表示時刻は分。ゲーム内で列車は**別々の平行な線路**を走り、同じx座標での出会いを示す（重なって隠れない）。

| ミッション | 変更可能 | 固定 | 目標 | 想定正解 |
|---|---|---|---|---|
| M01 中央駅で会おう | Bの速さ（12/18/24/30/36 km/h） | A=24 km/h、両方同時発車 | x=600m | B=24 km/h、t=1.5分 |
| M02 発車を遅らせて会おう | Bの発車待ち（0/0.5/1/1.5/2/2.5分） | A=12、B=24 km/h、Aは時刻0発車 | x=600m | B待ち1.5分、t=3分 |
| M03 800m地点で会おう | Aの速さ（12/18/24/30/36 km/h） | B=12 km/h、両方同時発車 | x=800m | A=24 km/h、t=2分 |

操作値は離散値のみで、初期値はすべて不正解。目標達成は距離誤差 `≤ 0.5m`。時計は小数1桁程度で読みやすく表示、**判定は丸める前の値で行う**。学校用の模式的な鉄道なので、列車の加減速・衝突・信号等は扱わない旨を説明欄に記載。

## 5. 数学・状態管理の契約

```
vA = kmhA × 1000 / 60 (m/分)
vB = kmhB × 1000 / 60 (m/分)
xA(t) = clamp(vA × max(0,t-delayA),0,1200)
xB(t) = 1200 − clamp(vB × max(0,t-delayB),0,1200)
```

出会いは `xA(t)=xB(t)`。遅れて発車する場合や端点での待機も含め、折点（各発車時刻、各終点到着時刻）で区分した**単調関数の線形補間**で解析的に求める。逐次描画のフレーム値から会う地点を算出しない。SVG線路・グラフ・文字表示は同じ純関数の値を参照。

状態：`idle → running → paused → completed`。条件変更は `idle` に戻し結果・グラフの旧表示をクリアする。アニメーションは `requestAnimationFrame` と `performance.now` の差分を使用し、タブが非表示になった間の時間を勝手に進めない。完了位置でアニメーション停止。速度は実時間1秒あたり約0.65ゲーム分（目標は実験値）。「結果を確かめる」ボタン後、成功・修正ヒントを確実に伝える。

## 6. ユーザビリティ

- ミッションごとに**操作できる項目は1つ**。固定値は「いまの条件」として比較表示だけ。
- ミッション選択は3件のみ。選択中が見分けられ、完了済みを見分けられる。勝手な次画面遷移はしない。
- 音声は使用しない。色以外に車両名「A」「B」、線の形・説明も使う。
- マウス・タッチ・キーボード（ネイティブinput range／buttons）対応。視覚的フォーカス、最低44pxタッチ領域、`aria-live`で結果発表。
- `prefers-reduced-motion:reduce` は短縮再生／即時結果モード。結果の因果説明は省かない。
- タイマー・比較表示はゲーム的なプレッシャーを与えず、失敗に減点なし。「どこで出会った？」から次の調整へつなげる。
- 保存は端末内のクリア済みミッションIDのみ。保存不可・破損時は通常プレイが継続する。名前・行動履歴は収集しない。
- 条件を動かすだけで正解を先に表示しない。正解の可視化は実行後。

## 7. アクセシビリティ・図版ガード

- ミニチュアSVG内の車両と駅は、それぞれ別の視覚レイヤー。駅名ラベルと車体を重ねない。
- グラフはSVGで動線を表し、軸ラベルが重ならない。画面リーダー向けの現在時刻・2車両の位置・出会い地点の情報をテキストでも保持。
- 数学の計算をCSS transformやSVGパス位置から逆算しない。SVG描画に使うパラメーターは検証済み0〜1200mの値のみ。
- 気泡や余計なラベルでスペースを埋めない。色は A:青、B:橙、達成:緑、注意:珊瑚に固定。

## 8. 検証と完成基準

**MVPの必須受入項目**

- 3ミッションすべてに正解・不正解があり、上表の値が一致する。
- 遅延発車0と正の値、速度の最小・最大値、タブ非表示からの復帰でも破綻しない。
- SVG上の位置、交点、時間、結果の日本語説明が一致する。
- 320/390/768/1280pxの実画面で横はみ出し・文字重なりを確認。できればFirefox・モバイルSafariでも確認。
- 初回起動→操作→実行→不正解→修正→正解→次のミッション→再読込で進捗復元まで通る。
- 広告・第三者解析・外部スクリプトなし。PikaLab既存の動作・画面は変えない。

**次期（MVP対象外）**：片方の途中停止、曲線グラフ、速度変化・加速度、数式入力、複数車両、駅の自由設計。いずれも既存3ミッションの質と学習効果を確認してから判断。

## 9. 開発手順・公開境界

- ①仕様書→②純関数の数学コアとNodeテスト→③独自の3D風SVGと操作→④Chromiumの実操作・サイズ監査→⑤読みやすさ修正→⑥ZIP+単独HTML作成→⑦GitHub PublicのDraft PR。
- ソース正本：`katakata0522/katakatalab-web`（Public）、本番配信権限・素材管理はPrivate側。Draft PRを作ってもPikaLab本番にデプロイしたとはみなさない。公開前にPublic CIとPrivate側の固定コミット取り込み・本番検証が必要。
- プライバシー方針：教育ページに広告・アフィリエイト・第三者の行動追跡を掲載しない。静的HTMLのみで起動し、ネット接続なしでも教材本体は動作する。
