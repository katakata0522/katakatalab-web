# PikaLab コンテンツUI・コピー編集原則

この文書は、PikaLabの新規ラボ・既存ラボ拡張・教育系ゲームで共通して守るレビュー基準。2026-10-15の「実験探偵ラボ」改善方針に基づく。

## まず削る（飾りテキスト禁止）

ラベル、見出し、説明、キャプション、タグは、次のいずれかの明確な役割を持つときだけ残す。

1. **何ができるか**を伝える
2. **何をすればよいか**を案内する
3. **どう比べるか**の判断材料を示す
4. **結果・状態・エラー・注意**を伝える
5. 学習上の**気づきや誤答の理由**を説明する

どれにも当てはまらず、画面の空きスペースや「賑やかし」のためだけに入れたコピーは削除する。消した分を別の飾り文で埋め戻さない。

### 削除対象の例

- `PIKALAB ORIGINAL / SCIENCE MYSTERY`のような自明な英語の飾りラベル
- 「1事件 約3分」のように、意思決定に役立たず実際の所要時間も保証しない表示
- `THE CASE FILES`など、日本語の見出しを英語で重複させただけの表記
- 同じ内容をヒーロー、説明文、カード、下部バナーで何度も繰り返す文章
- 「よくできました」だけで学習内容が伝わらない完了画面の追加コピー

### 残す例

- 「事件 05」「進捗 4/9」：作品を選び、続けるために必要
- 「実験A/B」「変える条件」「何を測る？」：判断の手がかり
- 誤答の理由、段階的なヒント：詰まったときに行動できる
- 「架空の実験計画」「結果は測るまで不明」：誤解を防ぐ注意

## 情報設計とゲーム性

- **主役はそのラボ固有の体験**。汎用ダッシュボード・カードの並べ過ぎを避ける。
- 視線の順番は「最初に実験・状況を見る → 比較する → 判断して操作する」。
- コンテンツが増えたらまず情報をグループ化し、ひと画面にすべて出さない。
- 達成率・バッジ・ランクを目的にしない。ゲームの攻略行動自体が学びになるようにする。
- 誤答時には嘲笑・減点より、具体的な誤解を解く説明を返す。
- 見た目の楽しさは、イラスト、操作の手応え、動き、世界観で表現し、文字を盛って作らない。
- ブランド色・操作色・検証済み・注意の状態色は役割を分ける。色だけで正誤や状態を伝えない。
- 調査前の画面に答えを示す配色・イラストがないかを検査する。

## 公開前のチェック

- 320px・390px・768px・1280pxの実画面で横はみ出し、文字切れ、重なり、フォーカス、タップ領域を確認。
- 長い説明や日本語・英数字混在で崩れない。文字サイズ拡大と読上げも確認。
- 問題データの正答・誤答・理由を教育面からレビューし、模式図を観察結果と誤認させない。
- 新規ラボは既存ラボの導線・本体の画面数を不要に増やさない。
- **教育エリア内は広告、アフィリエイト、第三者の行動追跡を配信しない。**
- スクリーンショットは更新対象のコミットで撮り直し、旧版を新しい画面の検証証拠として流用しない。
