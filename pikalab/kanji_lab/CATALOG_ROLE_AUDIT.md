# かんじ・ガッタイ・ラボ カタログ役割監査

## 目的

337字へ拡張したカタログを、単純な「字数」ではなく **ゲーム内で果たしている役割** で再監査する。

この監査では、珍しい字・常用外の字であること自体を削除理由にしない。

見るのは次の4点。

1. 通常学習として意味があるか
2. 同じ右/下パーツを別の左/上パーツと組み替える比較価値があるか
3. 「こんな字もあるんだ」という発見価値があるか
4. 「選択パーツを最低2正解にするためだけ」の数合わせになっていないか

---

## 現在の構造

### 左右モード

- 漢字: 283字
- 右パーツ: 92種類
- 1正解しか持たない右パーツ: 0
- **2正解ちょうどの右パーツ: 37種類**
- 3正解: 25種類
- 4正解: 19種類
- 5正解: 8種類
- 6正解: 3種類

つまり、2正解ルールを単純に撤廃すると、最大37種類の右パーツが1正解化する可能性がある。

### 上下モード

- 漢字: 54字
- 下パーツ: 24種類
- 1正解しか持たない下パーツ: 0
- **2正解ちょうどの下パーツ: 20種類**
- 3正解: 3種類
- 5正解: 1種類

上下モードは特に2正解パーツへの依存が大きく、単純な「1正解も許可」は一覧密度と試行錯誤性を悪化させやすい。

---

## 結論

### 原則

**通常のパーツ一覧では「2正解以上」を維持する。**

これはデータ都合の制約ではなく、現在の337字規模ではユーザビリティを守るための有効な制約と判断する。

ただし、2正解を満たすためだけに教材価値の弱い字を無制限に追加してはいけない。

したがって今後は、

> 1字を追加するために、価値の薄い2字目を機械的に追加しない。

> 2正解未満になる場合は、そのパーツを通常一覧へ常設すべきか、発見導線だけで扱うべきかを先に検討する。

という順序にする。

### C群の扱い

**現時点では物理削除しない。**

理由:

- 削除すると対応する右パーツが1正解になり、通常一覧の密度だけを下げる代わりに試行錯誤性も落ちる。
- 字自体は辞書で確認でき、発見価値はゼロではない。
- 本質的な問題は「存在」ではなく、全問/デイリー等で常用字と同率に出ること。

したがって、後続実装で **カタログ収録と通常出題比重を分離** するのが第一選択。

# 上下モード: 2正解パーツ全監査

## A. 維持 — 2字とも十分に価値あり

`云: 雲/芸`

`力: 男/劣`

`包: 雹/苞`

`十: 早/章`

`口: 杏/吉`

`古: 苦/居`

`台: 笞/苔`

`女: 安/妄`

`子: 字/李`

`林: 霖/森`

`生: 笙/星`

`田: 雷/苗`

`目: 盲/省`

`相: 箱/霜`

`糸: 累/紫`

`至: 室/屋`

特に `林: 霖/森` はこのラボの「未知の漢字との発見」を代表する良いペアなので維持する。

## B. 片方が補助寄りだが、主役を通常一覧に残す価値が高い — 維持 + 出題比重見直し

| 下パーツ | 主役側 | 補助/発見側 | 判断 |
|---|---|---|---|
| 令 | 零 | 苓 | 苓は準1級相当の植物字。零を通常一覧に保つためにも維持は合理的 |
| 元 | 完 | 芫 | 芫は1級相当の植物字。完の価値が非常に高いため、単純削除は得策でない |
| 旬 | 筍 | 荀 | 荀は1級相当・姓/草名。筍は発見価値が高く、旬パーツ自体は残したい |

## C. ペア全体の通常露出価値が低い — 最優先の間引き検討

### `本: 笨 / 苯`

- `笨`: 漢字ペディアで確認できる1級字。「あらい・おろかな」
- `苯`: 日本語教材としての根拠が他の収録字より弱く、以前の監査でも追加確認対象になっている
- どちらも現在の日本語利用者にとって接点が非常に薄い
- `本` を下パーツとして残すために2字を維持している形になりやすい
- この2字を通常一覧から外すと、下パーツ `本` そのものも削除できるため、**2字を削って1パーツ減らせる**
- 他の一般的・発見価値の高い漢字には影響しない

**現在の全337字で、物理的な間引きを最初に検討するならここが最有力。**

ただし、発見型サイトとしての方針を守るため、即削除よりも「深い図鑑/検索には残し、通常のパーツ一覧・通常クイズから外す」方式を先に実装できるなら、その方が望ましい。

# 2正解ではないが、露出比重を見直せる希少字

以下は削除しても対応パーツが2正解以上残るため、構造上の圧迫を起こさず整理できる候補。

ただし「珍しい」というだけで削らず、まず通常出題からの降格を優先する。

### 高優先で再評価

- `謨` / `摸`（莫）: `模 / 漠` が残り、莫の比較は成立する
- `搶` / `愴`（倉）: `槍 / 滄` が残る
- `沽` / `鈷`（古）: `枯 / 姑` が残る
- `佻` / `銚`（兆）: `桃 / 挑` が残る
- `晤` / `梧`（吾）: `語 / 悟` が残る
- `誥`（告）: `梏 / 浩` が残る
- `呵`（可）: `河 / 何` が残る
- `怡`（台）: `治 / 始` が残る
- `佼`（交）
- `佯`（羊）
- `坤`（申）
- `沾`（占）
- `鉦`（正）

これらは **物理削除候補ではなく「Deep Discovery / 通常出題外」候補** とする。

理由は、字形比較としては価値があるため。

# 推奨する次の実装

## 1. 物理削除を先にしない

まず、

- カタログに存在する
- 通常パーツ一覧へ出す
- 通常クイズへ出す
- デイリーへ出す
- おまかせ発見へ出す

を別々に制御できるようにする。

今はほぼ `KANJI_ALL` が全役割を兼ねているため、希少字を残すと通常クイズまで同率で希少化してしまう。

## 2. 役割は最低3層

### standard

通常ラボ / 通常クイズ / デイリー / 図鑑すべてに出る。

### discovery

通常ラボ・図鑑・おまかせ発見には出る。通常クイズ/デイリーでは低頻度または除外。

### deep

図鑑・検索・関連漢字・専用発見導線を中心に扱う。通常パーツ一覧には原則常設しない。

## 3. 「最低2字」の対象を明確化

`KANJI_ALL` 全体ではなく、**通常パーツ一覧に常設するデータについて2正解以上**を要求する。

これにより、発見用の1字パーツをデータとして保持しても、通常UIを圧迫しない。

## 4. 初回の実装対象

まずC群を通常クイズ/デイリーから分離し、利用感を確認する。

その後 `本: 笨/苯` を通常一覧から外すか判断する。

この順なら、珍しい漢字を消しすぎるリスクと、通常体験を散らかすリスクの両方を避けられる。
