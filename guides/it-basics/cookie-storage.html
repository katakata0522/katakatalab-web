CHAPTER 05｜Webの裏側と配信

CookieとlocalStorageとは？ブラウザ内データ保存の違いと注意点

一度ダークモードに切り替えると、次にページを開いたときも暗いままになっている。ログイン状態を維持してくれる。こうした「ブラウザが覚えていてくれる」機能の裏側には、CookieとlocalStorageの使い分けがあります。

執筆：かたかた 公開：2026年11月28日 読了目安：約4分
ひとことで言うと

Cookieはサーバー通信に自動添付される小さなメモ、localStorageはブラウザ内だけで使う大きめの保存棚です。

しくみの全体像

Webの通信（HTTP）は本来「前のやり取りを覚えていない（ステートレス）」仕組みです。そのため、ログイン状態やダークモードの好み、フォームの途中入力などを維持するには、ブラウザ側に小さな記憶領域を持たせる必要があります。

代表的なのが Cookie（クッキー） と Web Storage（localStorage / sessionStorage） です。名前は似ていますが、役割とセキュリティ上の扱いが大きく異なります。

3つの保存方法の使い分け

  • Cookie：容量は数KBと小さいですが、サーバーへ通信するたびにHTTPヘッダーへ自動で載せられます。ログインセッションの維持など「サーバー側が毎回確認したい情報」に向いています。HttpOnly 属性を付ければJavaScriptから読み取れなくでき、安全性も高められます。
  • localStorage：ブラウザ内だけに数MBほど保存でき、サーバーへは自動送信されません。タブを閉じても残るため、ダークモード設定・ツールの前回入力値・お気に入りプリセットなどの保存に最適です。
  • sessionStorage：localStorageと使い方は同じですが、そのタブを閉じると自動で消えます。一時的なウィザード入力や、その場限りの状態保持に向いています。

ブラウザ保存で気をつけたい3つの落とし穴

便利なブラウザ保存ですが、実装時に次の3点を見落とすと不具合やセキュリティ事故につながります。

  • プライベートブラウズや容量上限でエラーになる：localStorage.setItem() は設定や空き容量によって例外を投げることがあるため、必ず try / catch で囲みます。
  • 秘密情報や生パスワードは置かない：localStorageは同じオリジン上で動くJavaScriptから読めるため、XSS脆弱性があると盗み出されるリスクがあります。
  • 共有PCでは他人に残る：localStorageは手動で消さない限り残ります。個人情報を扱うツールでは「消去ボタン」や「保存しない設計」を明示するのが親切です。

この言葉が会話に出てくるとき

「テーマ設定はサーバーに送る必要ないから localStorage にしよう」
見た目の設定はブラウザ内完結で十分なので、CookieよりlocalStorageの方が通信量も増えずシンプルです。

「認証トークンは HttpOnly Cookie にしたい」
JavaScriptから直接アクセスできないCookieにすることで、XSSによるトークン抜き取りを防ぐ設計判断です。

勘違いしやすい点

  • 誤解1：localStorageに保存したデータは別のスマホやPCにも同期される。ブラウザ内のローカル領域なので、同じ端末・同じブラウザでしか共有されません。
  • 誤解2：シークレットモードを閉じても設定が残る。シークレットウィンドウのストレージは閉じた時点で破棄されます。

まとめ

  • サーバーへ毎回伝えたい認証情報にはCookie（HttpOnly等を活用）、ブラウザ内完結の設定にはlocalStorageを使う。
  • タブを閉じたら消したい一時データにはsessionStorageが向く。
  • localStorage操作は必ず try/catch で保護し、秘密情報や生パスワードは保存しない。

FROM THE LAB

KatakataLabでの実例

KatakataLabでは、全ページ共通のダークモード設定（theme）や一部ツールのプリセット保存にlocalStorageを使い、すべて try/catch で安全にガードしています。一方、パスワード生成ツールで生成した文字列自体は外部送信も自動保存もしない設計にしています。

関連ツールで試す：強力パスワード生成ツール →生成結果をサーバーへ送らず、ブラウザ内だけで安全にパスワードやパスフレーズを作成できます。

よくある質問

サイトで「Cookieを許可しますか？」とよく出るのはなぜですか？

ログイン維持だけでなく、アクセス解析や広告配信のために複数サイトをまたぐ識別子としてCookieが使われることがあり、プライバシー保護の観点から同意や説明が求められるためです。

localStorageの中身はどこで確認できますか？

ブラウザの開発者ツール（F12）を開き、「Application（アプリケーション）」タブの「Local Storage」から一覧確認や削除ができます。
