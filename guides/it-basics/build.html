CHAPTER 06｜制作と実装のしくみ

ビルドとトランスパイルとは？書いたコードから公開ファイルを作る工程

開発中のフォルダには TypeScript や JSX がたくさんあるのに、公開する `dist/` の中は数本の短いJSとCSSだけ——。この変身を行う工程が「ビルド」です。よく一緒に出てくるトランスパイル・バンドル・ミニファイとの違いも整理します。

執筆：かたかた 公開：2026年11月28日 読了目安：約4分
ひとことで言うと

ビルドは人間が書きやすいソースコードを、ブラウザが速く安全に実行できる公開用ファイル一式へ変換・まとめる工程です。

しくみの全体像

素のHTML・CSS・JavaScriptだけで作るサイトなら、書いたファイルをそのままサーバーへ置けます。しかし、TypeScript・React・SCSSなど現代の開発技術は、そのままではブラウザが直接解釈できません。

そこで、開発用に書きやすく整理したコードから、ブラウザが確実に速く動かせる公開用ファイル群（dist/ や build/）を作り出す一連の工程を ビルド（Build） と呼びます。

ビルドの中で起きている3つの変換

ビルドという言葉の中には、主に次の3つの処理が含まれています。

  • トランスパイル（Transpile）：TypeScriptの型注釈を取り除いたり、JSXを通常のJavaScript関数へ変換したり、新しい記法を幅広いブラウザで動くJavaScriptへ翻訳する処理です。
  • バンドル（Bundle）：数十個に分けて書いたJavaScriptファイルやライブラリを依存関係どおりにまとめ、通信回数を減らす処理です。
  • ミニファイ（Minify）：実行に不要な空白・改行・コメントを削り、変数名を短くしてファイル容量を軽くする処理です。

「ローカルでは動くのにビルドが落ちる」理由

開発サーバー（npm run dev）は速さを優先して最低限の変換だけで動かすことが多く、型エラーや未使用インポート、ファイルパスの大文字・小文字の違いを見逃す場合があります。一方、本番ビルド（npm run build）は全体を厳密に検査してまとめるため、公開前に潜在的なミスを止めてくれる防波堤の役割も果たします。

この言葉が会話に出てくるとき

「PR出す前にローカルで npm run build が通るか確認しておこう」
開発中の画面では見えていなかった型エラーや参照切れを、公開前に洗い出す習慣です。

「ビルド成果物のファイル名にハッシュが付いた」
内容が変わるたびにファイル名も変わるため、ブラウザに古いキャッシュが残る問題も同時に解決できます。

勘違いしやすい点

  • 誤解1：すべてのWeb制作で必ずビルドツールが必要。小規模な静的ページや素のJSツールなら、ビルドなしで直接書いた方がシンプルで長期保守しやすいことも多いです。
  • 誤解2：ビルド後の dist/ ファイルを直接編集すれば手っ取り早い。次にビルドした瞬間に上書きされて消える（先祖返りする）ため、修正は必ずソースコード側で行います。

まとめ

  • ビルドは「人間が書きやすいコード」を「ブラウザが速く読める公開ファイル」へ変換する工程。
  • トランスパイル（翻訳）・バンドル（結合）・ミニファイ（圧縮）の3要素で成り立つ。
  • 素のHTML/JSで十分な小ツールと、ビルドが活きる大きめアプリを使い分けると保守が楽になる。

よくある質問

コンパイルとトランスパイルはどう違いますか？

広い意味ではどちらも変換ですが、CやRustのように機械語へ落とすのをコンパイル、TypeScript→JavaScriptのように近い水準の別言語へ変換するのをトランスパイルと呼び分けるのが一般的です。

ミニファイしたコードのエラー位置はどう追うのですか？

ビルド時にソースマップ（.mapファイル）を生成しておくと、開発者ツール上で元のソース行番号へ対応づけてデバッグできます。
